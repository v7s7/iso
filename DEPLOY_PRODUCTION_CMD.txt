ISO Quality System - Production Deployment (Windows Command Prompt)
===================================================================

This package contains the approved migrated database. DO NOT run "npm run seed".
Seeding creates a different database and does not load the historical records.

Expected application address:
  Server:        http://localhost:4100
  Internal LAN:  http://10.27.17.20:4100


1. COPY THE PACKAGE
-------------------
Copy the extracted "iso-quality-production" folder to the server, for example:

  C:\Apps\iso-quality-production

Open Command Prompt and enter:

  cd /d C:\Apps\iso-quality-production\server


2. INSTALL NODE PACKAGES
------------------------
Node.js and npm must already be installed. Check them:

  node -v
  npm -v

Install exactly the versions recorded in package-lock.json:

  npm ci --omit=dev


3. CREATE THE SERVER CONFIGURATION
----------------------------------
Create the private .env file from the supplied template:

  copy .env.example .env
  notepad .env

Keep or set these values:

  PORT=4100
  CLIENT_URL=http://10.27.17.20:4100
  LDAP_URL=ldap://10.27.16.5
  LDAP_BASE_DN=DC=swd,DC=local
  LDAP_DEFAULT_UPN=swd.bh
  LDAP_ALT_UPN=swd.local
  LDAP_NETBIOS=SWD
  SUPER_ADMIN_USERS=a.alkubaesy
  ADMIN_DEPT_PREFIX=
  WEEKEND_DAYS=5,6

Leave DB_PATH blank. On the production server the data is kept outside the
code folder with DATA_DIR: see section 9.

Generate a new private JWT signing secret:

  npm run new-secret

LDAP_BIND_DN and LDAP_BIND_PASSWORD are optional. They are needed only for
browsing Active Directory from the Users screen. Normal AD sign-in works
without them. Never copy the laptop's .env file to the server.


4. VERIFY BEFORE STARTING
-------------------------
Run:

  npm run check-env
  npm run data-check

The environment check may show one warning when the optional LDAP browse
account is blank. The data check must end with "No issues found."


5. START THE APPLICATION
------------------------
Run:

  npm start

Or double-click START-ISO.cmd. Keep the Command Prompt window open. Then open:

  http://localhost:4100

Test sign-in with a real SWD Active Directory account. The published
@test.local accounts are disabled in this deployment database.


6. VERIFY FROM ANOTHER WORKSTATION
----------------------------------
Open:

  http://10.27.17.20:4100

If localhost works but this address does not, ask the server administrator to
permit inbound TCP port 4100 for the internal network. Do not expose this HTTP
service to the public internet.


7. BACKUP
---------
The backup command is safe while the application is running:

  npm run backup

Or double-click BACKUP-ISO.cmd. Backups are written to the backups folder in
the data folder (server\data\backups, or DATA_DIR\backups once DATA_DIR is set)
and are verified automatically with SQLite's integrity check.


8. FINAL GO-LIVE CHECK
----------------------
  [ ] Real AD user can sign in
  [ ] Abdulaziz is Supervisor and System Administrator
  [ ] Normal user sees only their own requests
  [ ] Supervisor sees only their department requests
  [ ] Power User sees organisation-wide reports
  [ ] One request can be created and closed
  [ ] Historical totals and a sample of request histories are correct
  [ ] npm run data-check reports no issues
  [ ] Server backup has been copied to the approved backup location


9. KEEP THE DATA OUTSIDE THE CODE FOLDER
----------------------------------------
Done once on the production server. Afterwards the code folder holds only
code, a pull cannot touch the data, and the backup of E:\Apps\data covers it.

IT first creates E:\Apps\data\iso with its permissions, including Modify for
the account the server runs as. Do not create it yourself: the moved files take
that folder's permissions.

On SWAPP the move is done with the backup tool in E:\Apps\_backup (its
docs\MOVE-DATA.md), from an elevated Command Prompt. The dry run changes
nothing and can run while the application is up:

  cd /d E:\Apps\_backup
  node src\cli.js move-data iso

Stop the application by pressing Ctrl+C in its Command Prompt window (answer Y
to "Terminate batch job") or by closing that window. That leaves the newest
changes in iso-quality.db-wal, which moves together with the database. Then:

  node src\cli.js move-data iso --apply

It refuses while port 4100 still answers. It moves everything in server\data
into E:\Apps\data\iso, checks every file, and renames server\data to
data.moved-<date> instead of deleting it.

Without the tool, move the files by hand in the same kind of Command Prompt the
server is started from:

  cd /d E:\Apps\iso\server\data
  move iso-quality.db E:\Apps\data\iso\
  move iso-quality.db-wal E:\Apps\data\iso\
  move iso-quality.db-shm E:\Apps\data\iso\
  move directory-link.csv E:\Apps\data\iso\

"The system cannot find the file specified" for a -wal or -shm file only means
it was not there.

Then add this line to server\.env, without quotes, and make sure DB_PATH is
blank or absent:

  DATA_DIR=E:\Apps\data\iso

Start the application. Its window must show:

  [DB] SQLite ready: E:\Apps\data\iso\iso-quality.db

Then, with it running:

  cd /d E:\Apps\iso\server
  npm run check-env
  npm run data-check

With DATA_DIR set, the server refuses to start rather than run on the wrong
data:
  - if the database is not in that folder, or is empty;
  - if iso-quality.db-wal was left in server\data and holds changes newer than
    the moved database;
  - if a database still in server\data changed more recently than the one in
    DATA_DIR (for example when only the .db was copied) and holds at least as
    many requests and users.
Each refusal says which files to move where. It only warns about an old
database or -wal in server\data that is older than the one in use, or about a
newer one with fewer requests or users (a new empty database, say): do not move
those next to the live database, move them out of the code folder.

Keep the DATA_DIR line. Without it the server refuses to start while
E:\Apps\data\iso holds the database and server\data does not, or while
server\data.moved-<date> shows the data was moved, rather than start on a new
empty database.

To go back, stop the server, move the files back into server\data (or rename
data.moved-<date> back to data, and E:\Apps\data\iso aside), then remove the
DATA_DIR line.


IMPORTANT
---------
Do not run npm run seed on this package.
Do not overwrite the live database (server\data\iso-quality.db, or the one in
DATA_DIR) during later application updates.
Do not commit or share server\.env; it contains the signing secret and may
contain an Active Directory service-account password.
